# Landing-page feature coverage

Audited 2026-10-15 against the landing page supplied in the task. This records code paths and automated verification, not a certification of live provider accounts or deployed jobs.

| Landing promise | App entry point and implementation | Outcome / conditions |
| --- | --- | --- |
| Create a brand and switch between brands | Brands; header switcher; `lib/actions/brands.ts`; `lib/auth/brand-auth.ts` | Implemented. Membership restricts data access. Report links with `brandId` validate membership and display the requested brand. |
| Compare brands side by side | Overview → Compare Brands; `lib/dashboard/overview.ts` | Implemented. Rows use each brand’s currency; combined monetary totals appear only for matching currencies. Blended ROAS is total revenue / total spend. No currency conversion is implied. |
| Shopify products, orders, refunds and sales together | Brands → Shopify & Ads; `lib/platforms/shopify/workspace.ts` | Implemented in preceding Shopify change. Includes pagination, product costs, missing-cost estimates, sync status, and orders/refunds. |
| Automatic product and order syncing | Shopify connection initial sync, Shopify webhooks, hourly `sync-platforms` job | Implemented; requires a working token, webhook registration and enabled cron. Product costs require inventory access. Older orders require Shopify’s applicable order-history permission. |
| View store ads and linked posts | Shopify & Ads → Ads & posts; `lib/platforms/ads/creative.ts` | Meta ad creatives and available published-post links; products matched by verified destination host and product handle. This is not a general organic-post importer. |
| Meta, Google, TikTok and Snapchat in one view | Campaigns; `api/brands/[id]/campaigns`; `lib/platforms/ads/report.ts` | Full paginated campaign report, including campaigns with no spend in the selected dates, plus cross-platform comparison. Provider credentials and account access are required. |
| Spend, budgets and cross-platform ROAS | Campaigns; `lib/platforms/ads/sync.ts`; `lib/platforms/ads/budgets.ts` | Date/platform filters, spend, revenue, impressions, clicks, conversions, ROAS, current daily/lifetime budgets and synced-day counts. Google shared and unavailable/ad-set budgets display as unavailable; TikTok budget mode distinguishes daily/lifetime/unlimited. |
| Manage ads from one workspace | Landing hero and feature section | Clarified to **monitor ads / ads reporting**. Campaign creation, budget changes and pausing remain in the native ad platform. No automatic ad-spend writes were added. |
| Revenue after refunds, COGS, fees, expenses and ad spend in profit | Profit; `lib/profit/calculations.ts`; `lib/profit/metrics.ts` | Overview now uses the same revenue calculation and brand timezone as P&L. Every report granularity exposes full cost breakdown; ROAS displays as a ratio. Fees and missing product costs are estimates. |
| Add expenses | Profit → Expenses; `api/brands/[id]/expenses` | Owners/managers can add, edit and remove one-time/daily/weekly/monthly expenses. Validates dates, amount precision and tenant ownership. Recurring expenses are allocated over their active dates; P&L refreshes after changes. Viewers/demo cannot mutate. |
| Configure default COGS | Brand settings; Shopify cost import and order cost snapshots | Existing default percentage retained. Actual inventory costs are entered in Shopify and imported; default percentage fills missing costs. Refunds reduce revenue; cost reversal for returned inventory is not inferred. |
| AI trends, anomalies and opportunities | AI insights; `lib/ai/analysis.ts`, `insights.ts`, `provider.ts` | Rule analysis works without a provider. Configured provider enhances advisory recommendations. Fixed equal-length comparison periods, empty-account warnings, zero AOV baselines, repeated-value regression, and daily-budget suggestions. Monetary output uses brand currency. |
| AI never changes campaigns automatically | Recommendations UI and API | Advisory only. Dismissal is local UI state; no campaign mutation endpoint is called. |
| Telegram daily and weekly summaries | Notifications; `lib/jobs/run.ts`, `lib/telegram/summary.ts` | Summaries include brand, period, currency, revenue after refunds, net profit, orders, spend, blended ROAS and top campaigns. Daily reports cover the last complete brand-local day; weekly reports cover the last complete Monday–Sunday in the brand timezone. |
| Timezone and quiet hours | Notification preferences; `lib/telegram/time.ts`; `vercel.json` | Jobs check hourly. Daily delivery begins at 09:00 recipient-local time; weekly delivery begins Monday at 09:00. Quiet hours defer to a later eligible hourly run that day. Period-based reservations prevent duplicate summaries. Extremely different brand/recipient timezones can mean their last complete reporting period differs. |
| ROAS, spend, revenue and campaign budget alerts | `checkAndTriggerAlerts` | Uses configured thresholds, brand timezone and quiet hours. Revenue compares complete days. Spend preference also enables current campaign daily-budget overrun alerts using its percentage threshold. New-order dedupe uses order identity, not a shared two-hour slot. |
| Read-only three-brand demo without connecting accounts | Demo authentication, `lib/demo/api.ts`, `lib/demo/data.ts` | Three sample brands with Shopify and all four ad platforms; profit, attribution, AI, notifications and billing. Demo mutations stop before database/provider calls. Campaign filters use sample date-range totals. Sample P&L expenses are illustrative rather than editable expense records. |

Existing dashboard, chart and API suites also cover comparison, brand switching, AI, notifications, attribution, billing, and demo isolation.

## Deployment and verification still required

1. Apply the preceding Shopify migration (`drizzle/0001_massive_hitman.sql`) if not already applied. This audit adds no database schema migration; expenses and campaign-budget columns already exist.
2. Deploy the updated application and hourly summary schedules. Configure `CRON_SECRET`, platform credentials, Shopify webhook verification, Telegram bot/webhook settings, and an AI provider if AI-generated recommendations are wanted. Provider apps must have the necessary approvals/access. Confirm the deployed scheduler supports these frequencies.
3. Verify initial and recurring sync with real connected accounts. Current automatic ad refresh covers yesterday and today; it does not backfill a full historical 30/90-day window or continually refresh older attribution. The Campaigns screen explicitly shows synced-day coverage. The existing manual sync API accepts a single date; older reports need explicit per-day resync.
4. Connect accounts whose currency matches the brand. Cross-platform revenue is platform-attributed and can overlap; P&L uses Shopify net sales for blended ROAS. Ads use the source account’s reporting-day boundaries; align account and brand timezones for consistent daily comparisons.
5. Use a dedicated test database to exercise persisted expense CRUD/tenant boundaries, SQL campaign aggregation, concurrent notification reservations and financial reconciliation; then smoke-test the deployed provider paths with authorized test accounts. Local fixture/browser success does not establish live provider delivery.
